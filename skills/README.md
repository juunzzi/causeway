# skills/

세션이 **필요할 때 읽는 절차서**를 두는 곳이다. `src/context.ts` 의 `defaultSkillsDir()` 가
이 디렉토리를 가리키고, 세션은 여기 있는 `SKILL.md` 를 `Read` 로 직접 연다.

보일러플레이트에는 예시 하나만 있다. 당신 조직의 절차를 여기에 더한다.

## 왜 프롬프트가 아니라 파일인가

절차를 전부 시스템 프롬프트에 실으면 **모든 턴이 그 비용을 낸다.** 열 개의 절차서 중 이번
질문에 필요한 건 보통 하나뿐인데, 나머지 아홉의 토큰도 매번 지불하고 그만큼 다른 맥락이
밀려난다.

그래서 프롬프트에는 "언제 무엇을 읽어라"만 한 줄씩 싣고(`SkillNote`), 본문은 파일로 둔다.
세션은 해당 상황이 왔을 때만 읽는다.

## 새 스킬 붙이기

### 1. 파일을 만든다

```
skills/<이름>/SKILL.md
```

첫 문단에 **언제 쓰는지**를 적는다. 세션이 이 파일을 열지 말지 판단하는 근거가 그 문단이다.
나머지는 절차 — 무엇을 어떤 순서로, 무엇을 하면 안 되는지.

### 2. 프롬프트에 한 줄 등록한다

`src/context.ts` 의 `chatSkillNotes` 배열에 넣는다:

```ts
const chatSkillNotes: SkillNote[] = [
  {
    when: "권한 부여·회수·조회 요청",
    path: join(skillsDir, "access/SKILL.md"),
    // notes 는 SKILL.md 가 담을 수 없는 **런타임 값**만 (env 로 정해지는 절대경로 같은 것).
    // 절차 설명을 여기 쓰지 마라 — 그러면 파일로 뺀 이유가 사라진다.
  },
];
```

`when` 이 프롬프트에 실리는 유일한 문장이라 **구체적이어야** 한다. "여러 일에 쓴다" 같은
설명은 세션이 언제 읽을지 판단하지 못해, 읽지 않거나 매번 읽는다.

### 3. 도구가 필요하면 도구도 붙인다

스킬은 절차서일 뿐 능력이 아니다. 절차가 외부 시스템을 만져야 한다면 `src/mcp/` 에 도구를
먼저 만든다 — [docs/EXTENDING.md](../docs/EXTENDING.md) 참고.

## 규율

- **스킬에 자격증명을 적지 마라.** 이 파일들은 세션이 읽는 평문이고, 세션의 대화는 트랜스크립트로
  디스크에 남는다. 키는 `.env` → in-process 도구 경로로만 흐른다.
- **"하지 마"를 절차서에 의존하지 마라.** 금지가 중요하면 도구의 입력 스키마에서 표현 자체를
  불가능하게 만든다. 스킬은 순응도에 기대는 장치라 경계로 쓰기엔 약하다.
- **절차가 바뀌면 파일을 고친다.** 세션이 읽는 것은 이 파일이지 당신의 기억이 아니다.
