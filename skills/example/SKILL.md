# 예시 스킬 — 복사해서 고쳐 쓰는 틀

**언제 읽는가:** 이 파일은 예시라 실제 발동 조건이 없다. 당신 조직의 스킬을 만들 때 이 첫
문단 자리에 **구체적인 발동 조건**을 적는다 — 세션이 이 파일을 열지 말지 판단하는 근거가
`src/context.ts` 의 `SkillNote.when` 과 이 문단, 둘뿐이다.

나쁜 예: "여러 운영 작업에 쓴다" → 언제 읽을지 판단이 안 돼 매번 읽거나 영영 안 읽는다.
좋은 예: "배포가 실패했거나 롤백 여부를 물을 때"

## 절차

1. **먼저 확인한다.** 무엇을 바꾸기 전에 현재 상태를 조회하는 단계를 맨 앞에 둔다. 세션은
   여러 턴에 걸쳐 같은 절차를 다시 밟는 일이 잦고, 확인 단계가 없으면 두 번 실행한다.
2. **한 번에 한 단계씩 보고한다.** 긴 절차를 통째로 수행한 뒤 결과만 알리면, 중간에서 어긋났을
   때 사람이 어디서 끊어졌는지 모른다.
3. **판단이 필요한 지점은 멈추고 묻는다.** 어느 지점이 그런지를 여기에 **명시적으로** 적는다.
   "애매하면 물어봐라" 같은 문장은 기준이 아니라 기분이라 실제로는 안 지켜진다.

## 하지 말 것

- 이 절차에 없는 부작용을 만들지 않는다.
- 결과를 요약할 때 **확인하지 않은 것을 확인한 것처럼 적지 않는다.** 조회에 실패했으면
  실패했다고 쓴다 — 빈 결과와 조회 실패는 다른 사실이다.
